COMANDOS PARA CONTROLAR EL ESTADO DEL CONTENEDOR
================================================
Proyecto: Automatizacion Mesa de Ayuda N8N
Stack Docker (proyecto fijo "mesa_local"): postgres, redis, backend, n8n, frontend, nginx

Documentacion detallada:
  - Arranque manual, backup y monitoreo : docs/operational-guide.md
  - Problemas frecuentes                 : docs/troubleshooting.md
  - Guia del workflow N8N                : docs/n8n-workflow-guide.md
  - Referencia rapida previa             : docs/Comandos_para_iniciar_proyecto.txt


REQUISITOS
----------
  - Docker Engine 24+ y Docker Compose v2
  - OpenSSL y curl en el PATH (los usa el arranque)
  - Python 3 (preflight de costo y de Gemini)

Verificar:
      docker --version
      docker compose version
      openssl version
      curl --version


PREPARACION (una sola vez por entorno)
--------------------------------------
1) Backend .env (OBLIGATORIO):
      cp App/Backend/.env.example App/Backend/.env

   Completar las 3 claves obligatorias:
      GEMINI_API_KEY                   (https://aistudio.google.com/apikey)
      JWT_SECRET_KEY                    -> python3 -c "import secrets; print(secrets.token_urlsafe(32))"
      PSEUDONYMIZATION_ENCRYPTION_KEY   -> python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

   IMPORTANTE: el .env del backend debe contener SOLO campos del backend.
   No agregar claves desconocidas (por ejemplo TWILIO_PHONE_NUMBER): el backend
   las rechaza y no arranca. El numero de Twilio se configura en N8N / la consola
   de Twilio, no aca.

2) .env de la RAIZ (recomendado para el stack completo):
      cp .env.example .env

   Definir COST_GUARD_SHARED_SECRET (misma variable para backend y n8n):
      python3 -c "import secrets; print(secrets.token_urlsafe(32))"
   Opcionales utiles: OPERATOR_EMAIL, SMTP_FROM_EMAIL y NGROK_AUTHTOKEN (tunel).

3) Dependencias del preflight:
      pip install -r scripts/preflight/requirements.txt


LEVANTAR (alta)
---------------
Un solo comando (recomendado): valida el .env, corre los preflight, genera los
certificados TLS si faltan, ejecuta "docker compose up -d --build", espera a que
los 6 servicios queden healthy y verifica los endpoints de salud.

      bash scripts/up.sh          # Linux / macOS (stack solo, sin tunel)
      .\scripts\up.ps1            # Windows (PowerShell) (stack solo, sin tunel)
      make up                     # stack COMPLETO + tunel ngrok (requiere NGROK_AUTHTOKEN)
      make up-core                # stack solo, sin tunel (equivalente a up.sh)

Alta manual (equivalente):
      bash openssl/generate-certs.sh
      docker compose -p mesa_local up -d --build
      docker compose -p mesa_local ps
      curl -k -fsS https://localhost/api/v1/health
      curl -k -fsS https://localhost/api/v1/health/db

Nota: el nombre de proyecto ya esta fijado como "mesa_local" en docker-compose.yml;
el "-p mesa_local" es explicito pero no obligatorio.


VERIFICAR ESTADO
----------------
      docker compose -p mesa_local ps
      docker compose -p mesa_local logs -f backend
      docker compose -p mesa_local logs -f n8n


ACCESO (una vez arriba)
-----------------------
      Web UI   : https://localhost/
      N8N      : http://localhost:5678   (usuario/password: default del compose
                 "admin" / "n8n_local_dev", o los que hayas puesto en
                 N8N_BASIC_AUTH_USER / N8N_BASIC_AUTH_PASSWORD del .env raiz)
      Postgres : localhost:5433  (db: mesa_de_ayuda, user: mesa, pass: mesa_local_dev)
      Redis    : localhost:6379

N8N (manual, una vez por entorno):
      1) Abrir http://localhost:5678
      2) Workflows -> Import from file -> n8n/workflow.json
      3) Configurar credenciales (Gemini, Outlook / IMAP-SMTP, Twilio)
      4) Activar el workflow

      NOTA: en una instancia YA configurada NO importar el workflow del repo
      encima (trae credenciales placeholder); parchear el workflow activo en sitio.


TUNEL PUBLICO (canal telefonia / Twilio)
----------------------------------------
      # "make up" ya lo levanta. Para levantarlo solo (stack ya arriba):
      make tunnel
      # Equivalente sin make:
      docker compose -p mesa_local --profile tunnel up -d ngrok


BAJAR (baja)
------------
      # Baja normal: se detiene y remueve; los volumenes PERSISTEN.
      # Con make (incluye el profile tunnel, detiene ngrok):
      make down
      # Equivalente sin make:
      docker compose -p mesa_local --profile tunnel down

      # Baja total: borra tambien los volumenes (base de datos y N8N limpios)
      docker compose -p mesa_local --profile tunnel down -v

IMPORTANTE: "down" SIN el profile tunnel NO detiene ngrok; al quedar vivo, la
red "mesa_local_default" no se elimina. Por eso tanto "make down" como el comando
de baja manual incluyen "--profile tunnel".


NOTAS
-----
  - Los volumenes postgres_data y n8n_data persisten entre bajas (salvo "-v").
    Un entorno nuevo arranca con base vacia; el backend corre "alembic upgrade head"
    al iniciar (migraciones + seeds de catalogos). Los usuarios y credenciales de
    N8N NO se recrean solos.
  - Cambiar POSTGRES_PASSWORD no actualiza un volumen ya inicializado: usar
    "down -v" o definir el valor viejo en el .env de la raiz.
  - El frontend compila VITE_API_BASE_URL=https://localhost en build time; para
    otro host hay que ajustarlo y reconstruir.
  - El dominio reservado de ngrok esta fijado (tameness-trilogy-unrefined.ngrok-free.dev)
    y debe coincidir en tres lugares: comando del compose, BACKEND_PUBLIC_BASE_URL
    (App/Backend/.env) y el whitelist de nginx/nginx.conf.
